이 FAQ는 NetApp Workload Factory for VMware에 대한 일반적인 질문에 답변합니다. 특히 VMware 워크로드 마이그레이션을 평가하거나 준비할 때 유용한 마이그레이션 계획 개념, 인벤토리, 스토리지, 비용, 지원 지역 및 EVS 분석에 중점을 둡니다.



[[migration-planning]]
== 마이그레이션 계획

.NetApp Workload Factory for VMware는 어떤 작업을 수행하는 데 도움이 됩니까?
온프레미스 VMware VM 구성을 분석하고 클라우드 환경을 위한 마이그레이션 계획을 생성하는 계획 센터 및 마이그레이션 어드바이저를 제공합니다. 계획 센터에서 저장된 VM 인벤토리 데이터 세트와 계획을 관리할 수 있습니다.

.어떤 마이그레이션 대상 및 외부 스토리지 옵션을 계획할 수 있습니까?
어드바이저는 다음과 같은 계획 수립을 지원합니다:

* *Amazon EVS, Amazon EC2 및 VMware Cloud on AWS*: Amazon FSx for NetApp ONTAP 외부 데이터 저장소.
* *Google Cloud VMware Engine*: Google Cloud NetApp Volumes 외부 NFS 데이터스토어.


각 대상에 대한 자세한 내용은 link:launch-migration-advisor-evs.html["Amazon EVS"], link:launch-onboarding-advisor-native.html["Amazon EC2"], link:launch-onboarding-advisor.html["AWS 기반 VMware Cloud"] 및 link:launch-migration-advisor-gcve.html["Google Cloud VMware Engine"]에 대한 마이그레이션 어드바이저 항목을 참조하십시오.

.마이그레이션 어드바이저는 계획을 생성할 때 무엇을 고려합니까?
어드바이저는 VM 구성을 분석하고, 마이그레이션할 VM을 결정하도록 지원하며, 클라우드 네이티브 외부 데이터스토어에 필요한 공간을 예측하고, 배포 계획을 제시합니다. 대상별 옵션에는 VM 선택, 용량 및 보호 설정, 스토리지 할당 등이 포함될 수 있습니다.

.Workload Factory는 모든 마이그레이션 대상에 권장 리소스를 프로비저닝할 수 있습니까?
Workload Factory는 Amazon EC2, Amazon EVS 및 VMware Cloud on AWS에 대한 배포를 지원합니다. Google Cloud VMware Engine의 경우, 이 플랜은 Terraform 환경에서 Google Cloud NetApp Volumes NFS 데이터스토어를 프로비저닝하기 위해 생성된 Terraform 코드를 제공합니다. link:deploy-fsx-file-system-native.html["Amazon EC2"], link:deploy-fsx-file-system-evs.html["Amazon EVS"] 및 link:deploy-fsx-file-system.html["AWS 기반 VMware Cloud"]에 대한 배포 플랜 항목을 참조하십시오.

.외부 데이터스토어는 VMware 스토리지와 어떻게 연동되나요?
FSx for ONTAP 또는 Google Cloud NetApp Volumes는 vSAN 스토리지를 보완할 수 있는 NFS 데이터스토어를 제공합니다. 이 스토리지는 컴퓨팅 성능과 독립적으로 확장되므로 호스트를 추가하지 않고도 스토리지 용량을 늘릴 수 있습니다.



[[vm-inventory]]
== VM 인벤토리

.마이그레이션 계획에 사용할 수 있는 VM 인벤토리 소스는 무엇인가요?
RVTools, Workload Factory VM 수집기 스크립트 또는 NetApp Data Infrastructure Insights에서 인벤토리를 제공할 수 있습니다. RVTools는 VM 구성 정보를 캡처하고, 수집기는 현재 VM 성능 데이터도 캡처할 수 있으며, Data Infrastructure Insights는 API 통신을 통해 인프라 정보를 제공합니다. 자세한 내용은 link:upload-vm-inventory.html["VM 인벤토리 데이터 업로드"]를 참조하십시오.

.RVTools 대신 VM 수집기를 선택하는 이유는 무엇일까요?
수집기는 VM 구성과 현재 읽기 및 쓰기 IOPS, 처리량 통계를 캡처하여 보다 정확한 계획 수립을 지원할 수 있습니다. RVTools는 구성 정보를 캡처하지만 이러한 성능 통계는 제공하지 않습니다. 자세한 내용은 link:capture-vm-configurations.html["VM 구성 캡처"]을(를) 참조하십시오.



[[costs-and-availability]]
== 비용 및 가용성

.VMware용 Workload Factory를 사용하려면 비용을 지불해야 합니까? 그리고 NetApp 라이선스가 필요합니까?
VMware용 Workload Factory는 무료로 사용할 수 있으며, 별도의 NetApp 라이선스도 필요하지 않습니다. 사용자는 어드바이저의 권장 사항에 따라 배포하는 AWS 리소스에 대해서만 비용을 지불합니다.

.VMware용 Workload Factory에서 사용할 수 있는 AWS 리전은 무엇입니까?
Workload Factory는 FSx for ONTAP이 지원되는 상용 리전에서 지원됩니다. 중국 리전, Secret Cloud 및 Top Secret Cloud는 지원되지 않습니다. 현재 AWS 리전별 가용성에 대해서는  https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/["지원되는 Amazon 리전"^]를 참조하십시오.

.EVS 절감액 계산기에서 무엇을 알 수 있습니까?
이 계산기는 FSx for ONTAP을 사용할 때와 사용하지 않을 때의 잠재적인 EVS 비용을 비교합니다. 지역, 물리적 CPU, 물리적 메모리, VM 스토리지 및 EVS 청구 플랜별로 예상치를 조정할 수 있습니다. FSx for ONTAP이 가장 비용 효율적인 스토리지로 확인되면 자세한 평가를 생성할 수 있습니다. link:calculate-evs-savings.html["EVS 절감액 계산하기"]을(를) 참조하십시오.



[[evs-well-architected-analysis]]
== EVS 잘 설계된 분석

.EVS의 잘 설계된 아키텍처 분석은 무엇을 검사합니까?
이 기능은 발견된 EVS 환경을 분석하여 안정성 및 보안 문제를 파악합니다. 문서화된 검사에서는 복원력을 위한 파티션 배치 그룹 분포와 클러스터 노드에 대한 EC2 중지 및 종료 보호 기능을 평가합니다. 결과에는 상태, 심각도, 영향을 받는 리소스 및 해결 지침이 포함됩니다. link:view-evs-well-architected.html["Workload Factory에서 잘 설계된 EVS 구성 구현"]을(를) 참조하십시오.

.EVS well-architected 분석은 얼마나 자주 실행되며, 어떤 접근 권한이 필요합니까?
검색된 EVS 구성은 AWS API를 사용하여 하루에 한 번 자동으로 스캔됩니다. vSphere 자격 증명 및 vCenter 연결은 필요하지 않습니다. VMware 워크로드에 대한 보기, 계획 및 분석 권한이 있는 AWS 자격 증명과 하나 이상의 검색된 EVS 환경이 필요합니다. 자세한 내용은 link:view-evs-well-architected.html["EVS의 잘 설계된 분석 요구 사항"]을(를) 참조하십시오.
